# OSS 라이선스 비교 및 선택 기준

## 목적과 결정 배경

ArtworkGuard를 공개 저장소로 운영하면서 외부 사용과 기여를 허용하되, 재배포 조건을 이해하기 쉽게 유지할 라이선스가 필요합니다. 현재 저장소의 `LICENSE`는 MIT License이며, 이 문서는 그 선택 근거와 제3자 의존성 검토 기준을 기록합니다.

> 이 문서는 프로젝트 운영 기준이며 법률 자문이 아닙니다. 상용 배포나 고위험 의존성 도입 전에는 전문가 검토가 필요합니다.

## 선택 기준

ArtworkGuard에는 다음 순서로 판단합니다.

1. **기여 접근성**: 학생, 개인 개발자와 조직 내부 팀이 복잡한 의무 없이 실습·재사용할 수 있어야 합니다.
2. **배포 유연성**: 학습용, 내부 서비스, 상용 PoC 등 여러 형태로 활용할 수 있어야 합니다.
3. **준수 비용**: 작은 팀이 고지와 의존성 목록을 지속적으로 관리할 수 있어야 합니다.
4. **특허 위험**: 특허 허여가 핵심인 기업 협업 단계에서는 Apache-2.0 전환 또는 별도 기여 계약을 검토합니다.
5. **생태계 호환성**: 도입하는 라이브러리와 모델·데이터·이미지 라이선스를 코드 라이선스와 별도로 확인합니다.

## 결정

현재 단계에서는 **MIT License를 유지**합니다.

- 짧고 이해하기 쉬워 외부 기여와 교육 목적 재사용의 장벽이 낮습니다.
- 비공개 내부 서비스와 공개 파생 프로젝트 모두에 적용하기 쉽습니다.
- 기존 저장소가 이미 MIT로 공개되어 있어 불필요한 라이선스 변경 비용을 피합니다.

다음 조건이 생기면 결정을 재검토합니다.

- 조직 간 공동 개발에서 명시적인 특허 허여가 요구될 때
- 강한 상호 공개 의무가 프로젝트 목표가 될 때
- 도입 의존성의 라이선스가 MIT 배포와 충돌할 가능성이 있을 때
- 법무 또는 보안 검토에서 추가 고지·책임 제한이 필요하다고 판단할 때

## 기여 및 의존성 준수 체크리스트

- [ ] 새 파일의 출처와 저작권 상태를 확인했다.
- [ ] 복사한 코드, 모델, 데이터, 폰트와 이미지의 라이선스를 기록했다.
- [ ] GPL/AGPL 등 카피레프트 의존성은 배포·네트워크 제공 영향을 검토했다.
- [ ] Apache-2.0 의존성의 `NOTICE` 및 변경 고지 조건을 확인했다.
- [ ] 생성형 AI 산출물이나 사용자 업로드 자료에 제3자 권리가 포함되지 않았는지 확인했다.
- [ ] 배포물에 저장소의 MIT 저작권 및 라이선스 고지를 포함했다.
- [ ] 판단이 불명확한 자산은 승인 전까지 병합하지 않았다.
