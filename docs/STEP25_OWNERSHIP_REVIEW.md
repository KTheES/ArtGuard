# STEP 25 소유권 보조 자료 제출·검토

등록 작품의 게시 URL과 설명을 선택적으로 제출하고 관리자가 검토하는 API입니다. [원본 파일 첨부 API](STEP25_SOURCE_FILES.md)도 추가됐으며 PSD/Procreate의 전체 내부 분석은 포함하지 않습니다. 기존 작품 등록·탐지는 자료 제출 없이 사용할 수 있습니다. 자료 승인 여부를 신고 가능 여부나 법적 소유권 인증으로 사용하지 않습니다.

## API

- `POST /api/v1/artworks/{artworkId}/ownership-claims`: `{"publicationUrl":"https://example.com/art","statement":"원본 게시와 제작 과정 설명","authorized":true}`
- `GET /api/v1/artworks/{artworkId}/ownership-claims?page=0&size=20`: 소유자 본인의 자료 이력
- `GET /api/v1/admin/ownership-claims?status=PENDING&page=0&size=20`: 관리자 검토 목록
- `PATCH /api/v1/admin/ownership-claims/{id}`: `{"status":"ACCEPTED","reason":"자료 간 일치 사항을 검토함","version":0}` 또는 REJECTED

제출에는 본인 소유의 활성 작품, 활성 계정, 이메일 인증, 명시적 권한 확인이 필요합니다. 사용자당 제출 요청은 분당 3회입니다. URL은 HTTPS, 자격 증명 없음, 기본 포트로 제한하며 서버에서 URL을 열거나 콘텐츠를 수집하지 않습니다. URL·설명은 신뢰할 수 없는 입력이므로 향후 화면에서는 텍스트로 이스케이프해야 합니다. 비공개 접근 토큰·비밀값·불필요한 개인정보를 자료에 포함하지 않아야 합니다.

작품당 PENDING은 하나입니다. 검토 종료 후 보완 자료를 새로 제출할 수 있지만 기존 자료·검토 결과를 덮어쓰지는 않습니다. 검토 결과는 PENDING → ACCEPTED/REJECTED 한 번만 변경할 수 있고 사유가 필수입니다. version으로 동시 수정 충돌을 감지합니다. 관리자 권한은 JWT와 현재 DB 역할 양쪽에서 검사하며, 자기 자료는 검토할 수 없습니다. 삭제된 작품·비활성 사용자의 자료는 조회·검토 대상에서 제외됩니다.

ACCEPTED는 보조 자료의 내부 검토 완료를 뜻합니다. 실제 창작자·권리 보유자에 대한 법적 인증, 소셜 계정 소유 확인, 이미지 유사도 판단을 대체하지 않습니다. 이전 승인 이력과 새 반려 이력은 각각 보존되며 단일 소유권 인증 배지를 자동 부여하지 않습니다.

V22는 제출 내용 불변성, 검토 중복 방지, 자기 승인 차단, 관리자 역할 검사와 감사 이벤트를 추가합니다. 감사 기록에는 상태와 행위자 ID만 저장하고 URL·설명 전문은 복제하지 않습니다. 아직 삭제·보존기간 정책은 별도 작업이며 자료를 실제 운영에 수집하기 전 검토해야 합니다.

## 검증 및 다음 항목

서비스·컨트롤러 테스트는 타인 작품, 미인증, 중복 제출, 관리자 권한, 자기 승인, stale version 및 요청 형식을 검사합니다. PostgreSQL 통합 테스트에는 실제 V22 적용과 불변성·재제출·감사 기록 검증을 포함했습니다. Docker 부재로 DB 통합 실행은 미완료입니다. 실제 사용자 자료 제출·외부 URL 방문은 하지 않았습니다.

소셜 계정은 [프로필 코드 수동 확인](STEP25_SOCIAL_ACCOUNT_CHECK.md) 방식으로 추가했습니다. 원본 자료 첨부까지 기본 기능을 구현했으며 다음 개발 항목은 STEP 26 감사 로그입니다.
