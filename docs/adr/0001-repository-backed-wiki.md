# ADR-0001: Wiki 원본을 저장소에도 보관

- 상태: 승인됨
- 날짜: 2026-10-14
- 결정자: ArtworkGuard 프로젝트
- 관련 Issue/PR: 이 변경의 Pull Request

## 결정 사항 및 배경

GitHub Wiki는 읽기 편하지만 애플리케이션 소스 PR과 분리되어 변경 검토와 복구가 어렵습니다. Wiki 최소 문서 세 개를 공개하면서도 동일 내용을 코드 리뷰와 백업 대상으로 유지해야 합니다.

## 고려한 선택지

1. Wiki에만 작성: 접근성은 좋지만 일반 PR 검토와 함께 변경하기 어렵습니다.
2. 저장소 문서만 작성: 검토는 쉽지만 과제에서 요구한 Wiki 탐색 경험을 제공하지 못합니다.
3. 저장소 원본과 Wiki를 함께 유지: 중복 관리 비용은 있지만 검토 가능성과 접근성을 모두 확보합니다.

## 결정

`docs/wiki/`를 검토 가능한 원본으로 두고 GitHub Wiki에 동일한 문서를 게시합니다. 각 문서는 Home, Getting Started, Development Guide, Troubleshooting으로 상호 연결합니다.

## 아키텍처 영향

런타임 구성에는 영향이 없습니다. 문서 배포 경계만 애플리케이션 저장소와 GitHub Wiki 두 곳으로 나뉩니다.

## API 영향

없음.

## 결과와 위험

PR에서 Wiki 내용을 검토하고 손실 시 복원할 수 있습니다. 반면 두 위치가 달라질 수 있으므로 Wiki 변경 시 `docs/wiki/`도 같은 작업에서 갱신해야 합니다.

## 트러블슈팅 및 운영

링크 오류는 네 문서의 하단 탐색 링크와 Home 목록을 확인합니다. Wiki 게시 실패 시 저장소 원본을 기준으로 복구합니다.

## 회의 노트 및 액션 항목

- [ ] Wiki를 변경하는 PR에서 저장소 원본과 게시본 일치 여부 확인

## FAQ 및 온보딩 영향

신규 참여자는 Wiki의 Getting Started에서 시작하고, 변경 규칙은 Development Guide에서 확인합니다.
