# STEP 25 원본 자료 파일 첨부

기존 소유권 보조 자료 요청에 PSD 또는 Procreate로 선언한 원본 파일을 선택적으로 첨부하는 API입니다. 업로드한 원본 바이트를 별도 저장하고 SHA-256·크기·검사 범위를 기록합니다. 파일은 검토 근거이며 창작자·저작권 소유를 자동 인증하지 않습니다.

## API

1. 기존 소유권 자료 제출 API로 PENDING 요청을 만듭니다.
2. `POST /api/v1/ownership-claims/{id}/source-file`에 multipart `format=PSD` 또는 `PROCREATE`, `file`을 보냅니다. 본인 요청·활성 계정·이메일 인증이 필요합니다. 요청당 파일 하나, 최대 20 MiB, 사용자당 분당 2회입니다.
3. 소유자는 `GET /api/v1/ownership-claims/{id}/source-file`로 메타데이터를 조회합니다.
4. 관리자는 `GET /api/v1/admin/ownership-claims/{id}/source-file`로 메타데이터를 확인하고 `/download`를 붙인 경로에서 원본 바이트를 내려받습니다. JWT와 현재 DB 관리자 권한을 검사합니다. 다운로드는 관리자당 분당 10회입니다.
5. 기존 소유권 검토 API에서 검토 사유와 승인·반려를 기록합니다. 레이어·작성 이력·원본 작품과의 관계는 관리자가 별도로 판단해야 합니다.

기존 검토 목록에는 첨부 내용이 자동 포함되지 않으므로 관리자 클라이언트는 메타데이터 API도 조회해야 합니다. 업로드 후에는 교체·삭제할 수 없습니다. 검토 종료 뒤 보완 자료가 필요하면 새 검토 요청을 만듭니다. 첨부 중에는 검토 요청 행을 잠가 검토 완료와의 경합을 막습니다. 네트워크 재시도 시 이미 첨부됐다면 409가 반환되므로 메타데이터를 확인합니다.

## 검사 범위

PSD는 [Adobe 형식 명세](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/)의 버전 1 헤더, 채널·크기·비트 깊이·색상 모드, 세 섹션 길이와 압축 식별자 범위를 확인합니다. 검사 결과는 `PSD_HEADER_AND_SECTION_BOUNDS_ONLY`입니다. 전체 이미지 디코딩·레이어 분석·무결한 PSD 보증은 아니며 PSB는 거절합니다.

[Procreate 공식 파일 형식 안내](https://help.procreate.com/procreate/handbook/gallery/gallery-file-types)는 네이티브 형식을 설명합니다. 이번 구현은 내부 Procreate 스키마를 검증하지 않습니다. PROCREATE로 선언한 파일을 ZIP 컨테이너로 읽을 수 있을 때만 수용하며 결과는 `ZIP_CONTAINER_ONLY_NOT_PROCREATE_AUTHENTICATED`입니다. 일반 ZIP도 이 검사에 통과할 수 있습니다. ZIP이 아닌 향후 형식이나 제한을 넘는 유효 파일은 수용하지 못합니다. 실제 앱 호환성은 별도 수동 검증이 필요합니다.

ZIP 항목은 최대 2,000개, 전체 해제 크기는 64 MiB입니다. 경로 탈출 표기·중복 경로·손상 CRC·잘린 중앙 디렉터리를 거절합니다. 임시 ZIP 파일만 생성하고 항목을 파일시스템에 추출하지 않습니다. 임시 파일은 검사 후 삭제하며 삭제 실패에 대비한 운영 임시 디렉터리 정리 정책이 필요합니다.

## 저장과 제한

저장 키는 서버가 생성하며 클라이언트 파일명이나 원본 경로를 사용하지 않습니다. 기존 S3 저장소 설정을 사용하며 `application/octet-stream`으로 기록합니다. 다운로드는 짧은 공개 링크 대신 관리자 API를 통해 전달하고 SHA-256을 재검사합니다. 강제 attachment·nosniff·no-store 헤더를 적용하며 브라우저 미리보기를 제공하지 않습니다. 내려받은 파일명은 안전한 `.bin`이며 사용자가 선언 형식을 확인한 뒤 원본 프로그램에서 처리해야 합니다.

악성코드 검사·샌드박스 앱 실행·PSB·대용량 업로드는 구현하지 않았습니다. 헤더/컨테이너 검사를 통과해도 안전한 파일이라고 보장하지 않습니다. 운영자가 실제 파일을 다루기 전 별도 악성코드 검사와 격리된 검토 환경을 준비해야 합니다. S3 저장 후 DB 실패 시 미참조 객체가 남을 수 있으며 정상 참조를 확인한 뒤 정리하는 운영 작업이 필요합니다. 업로드 파일의 내부 개인정보를 자동 제거하지 않습니다.

V24는 첨부 메타데이터 불변성·검토 상태 확인·해시와 크기 감사 기록을 추가합니다. 파일 자체의 S3 Object Lock, 보존기간·삭제 정책은 별도 운영 항목입니다. 실제 저장소 업로드·다운로드와 PostgreSQL 마이그레이션 실행은 아직 검증하지 않았습니다.
